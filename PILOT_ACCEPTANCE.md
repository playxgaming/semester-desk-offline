# Browser pilot acceptance

The current pilot target is the browser. Use a fresh test profile or export a complete backup before entering real pilot data. Local connector, hosted site and Android each use separate storage origins.

## Student journeys

1. Import a syllabus from text, a digital PDF, and a clear printed English photo. For a scanned PDF, use local text recognition (up to 10 pages). Crop/rotate a photo, review every line and save. Reopen the source and download the original. Disconnect the network and repeat OCR after the app's initial offline installation completes.
2. Add teaching reference text/PDF. In Notes → AI notes select one topic, format and level, then only the excerpts needed. Check what will be sent before generating. Compare every mathematical step, definition, example and citation against your material. Record provider/model and any missing or incorrect claim. Structural quotation checks do not establish correctness.
3. Edit a generated draft. Generate another draft, verify the earlier edits remain, and reopen both offline. Make cards, edit proposed questions/answers before adding, then take a quiz. Reload mid-quiz, resume from history, finish, inspect mistakes and approve revision blocks for a chosen day.
4. Import a timetable photo. Check crop, course aliases, sections, Week A anchor and Week B preview. Exclude other sections. Resolve highlighted overlaps before import. Verify alternating weeks against Today/attendance on the corresponding dates.
5. Configure Planner → Study hours. Add an early deadline, a class inside your study window and a manual block. Verify proposed blocks avoid class/fixed times and finish before the exact deadline. Rebuild and check the saved times. Empty windows should produce no new timed work. Untimed legacy fixed blocks reserve minutes; their exact location is unknown.
6. Record an application with a CV and move it beyond Sourced. Inspect its recorded CV snapshot. Edit the original resume/profile and verify the snapshot remains unchanged. Legacy submitted applications capture their current CV on their next save; this does not reconstruct a historical document.
7. Search for text inside notes, sources, cards and applications. Delete a synthetic record, find it in Trash and restore it. Restore a parent course/note before a dependent record. File bytes may expire after the existing recovery grace period; use complete backups for durable retention.
8. Export a complete JSON backup, restore into a separate browser profile and verify files, OCR sources, quiz progress, note provenance, CV snapshots and study windows. Keep the source profile until the restored copy is checked.

## Record real AI quality

For each real course example record the topic, source pages, provider/configured model, note format/level, supported claims, unsupported claims, omissions, equation rendering and practical usefulness. Reject any invented citation or misleading explanation. No real course material or live-provider quality is certified by deterministic/mock tests.

Use **Quality reviews** in the navigation (under More on mobile). Notes also has **Review note quality**; a saved course source has **Review extraction quality**. Inspect the saved content, compare it with your original course material, then record the four checks and a verdict. Usable requires all four checks to pass. For rejected/needs-changes items, record a specific issue or correction. Reviews make no AI request.

The screen reviews the effective saved note draft, including source excerpts/provider details where available, or the saved document text and extraction pages. If the content or source context changes, the old verdict displays **Changed since review**; inspect the latest content and add a new review. Each prior review retains its exact content. Pinning a note does not invalidate its review. A concurrent edit while the form is open prevents saving an outdated verdict.

Export the local JSON review report to collect evidence across a pilot; it contains reviewed text and source context, so choose deliberately what to share. Complete app backups include review history. The report is readable evidence, not a replacement for a restorable complete backup. Automated tests cover synthetic review workflows only; real-course factual accuracy remains for the student pilot to evaluate.

## Android later

Build/signing configuration can be checked locally. Phone acceptance still needs install, upgrade with the same signer, data retention, offline OCR memory/performance, notification permissions, alarm delivery while closed and backup restore on the actual phone. A browser run or asset sync does not verify these.
